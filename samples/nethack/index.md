# NetHack developer documentation

Documentation for the developers and agents of this system, not for end users.

It stays in sync with the code. Maintaining it is part of the development process and the Definition of Done.

## Wavelet Architecture

Docs follow a wavelet model: progressive refinement, like image compression. Each layer is independently useful.

- **L1** (`L1-vision.md`): Blurry but complete. Business context, product strategy. Read first for any product decision.
- **L2** (`L2-architecture.md`): CTO whiteboard. Tech stack, subsystems, data flow. Read before implementation work.
- **L3** (`L3-modules.md`): Module deep dives. How each technical piece works. Read when working in a specific module.
- **L4** (`L4-operations.md`): Operations. Git workflow, testing, dev setup, deployment, debugging. Read when you need process guidance.
- **Glossary** (`Glossary.md`): Domain language. Should probably be read by all agents.

## How to read it

**IMPORTANT: Always, before diving into the code or evaluating the project:**

> **Choose at least one document from each layer from L1 to L3** before working with the code.
> Choose as many additional documents from L1 to L4 as you deem useful for the task at hand.

Pick the most relevant document in each layer. If a layer has nothing that applies, or is still empty, skip it and say so. Then pick the documents each implementing agent should read before it starts, by the same method, and put that list into the story or plan.

## Existing documentation outside the pyramid

These files stay where they are: they are shipped with the game, owned by the DevTeam's tooling, or too long to move. The pyramid links to them instead of copying them.

- `README`, `Files` (every file in a distribution), `Porting`, `Cross-compiling`, `Contributing.md` in the repository root.
- `doc/`: `Guidebook` (for players), man pages, `window.txt`, `sound.txt`, `lua.adoc`, `fixes*.txt` change lists.
- `DEVEL/`: `Developer.txt`, `code_style.txt`, `code_features.txt`, `git_recipes.txt`.
- Platform notes: `sys/*/Install.*`, `sys/unix/NewInstall.unx`, `sys/unix/README.hints`, `win/*/Install.*`.

## Keeping it current

- Update the docs your change makes stale.
- A module has one home: a `##` section in its layer file, or its own file in the layer folder when it passes about 100 lines. Never both, and no `index.md` inside a layer folder.
- Start each section with one sentence of at most 100 characters that says what it covers. The routing table copies it.
- One fact has one home. Link to it instead of restating it.
- Follow `house-style.md`.
- When your edits are finished, run `node tools/refresh-pyramid.js dev-docs` and fix what it reports. The skill `/refresh-pyramid` helps when it reports findings.
